# rv64

The QEMU virt target boots at physical `0x80000000` in machine mode with
`-bios none`. The kernel remains in M-mode. Its native execution backend enables
Sv39 for U-mode and returns directly to an M-mode trap bridge.

Implementation:

- `src/arch/rv64/boot.S`: stack setup, BSS clearing and `kernel_main` entry on
  hart 0, and the park loop of every other hart.
- `src/arch/rv64/smp.cpp`: hart discovery from the DTB, hart start, IPIs and the
  secondary idle wait.
- `src/arch/rv64/platform.cpp`: NS16550 UART, framebuffer and platform I/O.
- `src/arch/rv64/execution.cpp`: protected address spaces, page validation,
  guarded user copies and native execution lifecycle.
- `src/arch/rv64/execution.S`: M-mode/U-mode transition, syscall and exception
  capture, CLINT timer interruption and context restoration.

User virtual addresses occupy `0x40000000..0x80000000`. Each address space maps
only its supplied user pages. PMP permits page-table walks and accesses to the
reserved backing storage; Sv39 PTEs enforce user read/write/execute permissions.
Writable executable mappings, duplicate mappings and stale handles are rejected.
Each address space owns a root, a middle table and one leaf table per
populated 2 MiB, allocated from the runtime's table storage and released with
the space; the slot table grows with the number of spaces. Allocation of
application data pages belongs to the native runtime.

`UserFrame.registers[i]` stores RISC-V register `xi`; `pc` and `sp` hold the
resume PC and stack. The bridge preserves integer registers, F/D registers and
FCSR, and restores the calling kernel's callee-saved state and machine CSRs.
User `ecall` uses `a7` for the number and `a0..a5` for arguments; the saved PC is
advanced past the instruction before returning to the kernel. CLINT interrupts
return a timer trap after approximately 10 ms on QEMU virt's 10 MHz timebase.

The hardware acceptance probe is independent of xmake configuration:

```sh
python3 scripts/test_native_rv64.py
```

It executes real U-mode instructions to validate syscall return, two timer
interruptions, register and floating-point restoration, read-only protection,
kernel address isolation, separate user page tables, safe-copy bounds and stale
address-space rejection. On `-smp 2` it then discovers both harts, starts hart
1, runs user code there beside hart 0's own entries, checks that hart 1's timer
is its local tick, that a remap of hart 1's space first takes it out of U-mode
with an IPI, and that an IPI ends its idle wait. It routes the UART's line to
hart 1, whose user trap and idle wait run the top half, ends hart 1's device
wait from hart 0's top half with an IPI, and retargets hart 1's line away.
Success emits
`RV64_NATIVE_PASS scope=hardware`.

## Secondary harts

QEMU `-bios none` starts every hart at `_start` with `a0 = mhartid` and
`a1 =` the DTB, and there is no SBI. Harts other than 0 park in `boot.S` before
touching a stack or BSS: `mie` holds only MSIE, `mstatus.MIE` stays clear, and
each wake clears the hart's CLINT MSIP and checks its entry of
`ok_rv64_hart_mailbox` (in `.data`, which hart 0 does not clear). Bring-up
(`ok::smp::start_secondary_cpus`) parses the DTB's `/cpus`, fills the entry with
the stack top, the CPU's per-CPU block and its logical id, publishes the entry
point with a release store and raises the hart's MSIP after a fence: an
HSM-shaped hart start inside the M-mode kernel, reported as
`ap_start=clint-msip`. The hart programs its own PMP and `mtimecmp` and runs
`ok_smp_secondary_main`. Harts 16 and up park for good.

`tp` points at the hart's per-CPU block, which holds its logical id (read by
`cpu_index()`), the user `mie`, the quantum's `mtimecmp` deadline and whether
the hart is in a native entry. `boot.S` sets it for hart 0 and the mailbox for
the others; the entry bridge saves the kernel's `tp` and restores it after the
trap. Each hart uses its own `mtimecmp` (`0x2004000 + 8 * mhartid`).

IPIs are CLINT MSIP writes after a fence that orders the reasons before them;
the receiver clears its MSIP before draining. In U-mode every hart takes its
timer and MSIP; only hart 0 takes machine external interrupts, and only its
PLIC M-mode context is enabled. A trap with cause 3 returns
`TrapKind::interrupt` after the IPI is acknowledged, without a PLIC claim. Hart
0's timer is the system tick; another hart's is its local tick
(`ok::smp::local_tick`). A secondary idles with a one-shot 10 ms `mtimecmp` and
MSIE, and hart 0's idle wait also ends on its MSIP. Before `remap` or
`destroy_space` changes a space's tables, `ok::smp::quiesce_root` sends every
other hart running under it out of U-mode; the trap path's `sfence.vma` and the
next entry's discard any stale translation. Address-space slot lookups at entry
take a backend spin lock against concurrent slot-table growth.

PLIC external interrupts on secondary harts, RISC-V vectors, SBI integration and
an S-mode kernel are separate milestones. Existing architecture profile strings
describing `stvec`, PLIC/SBI and `sret` remain target metadata, not evidence of
those features.
