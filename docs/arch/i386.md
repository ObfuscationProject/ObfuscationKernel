# i386

The `i386` profile models 32-bit x86 with 4 KiB pages, little-endian memory, and
ring 3 user mode.

Implementation:

- `src/arch/i386/ops.cpp`: architecture operations.
- `src/arch/i386/boot.S`: protected-mode kernel entry, `.bss` clearing, and
  bootstrap stack setup.
- `src/arch/i386/linker.ld`: freestanding kernel image layout.
- `src/arch/x86_64/boot16.S`: shared BIOS-loaded first-stage kernel boot sector
  used by both x86 profiles.

The profile provides IDT/PIC/APIC metadata, `int 0x80`/`sysenter` syscall
metadata, `iret`/TSS user-transition metadata, and guarded x86 inline assembly
for cycle counters, memory fences, interrupt control, and halt/yield behavior.

## Bring-up Plan

- Interrupts: IDT with interrupt/trap gates and legacy PIC/APIC routing.
- Memory: two-level paging, higher-half kernel mapping, user/supervisor page
  permissions.
- User mode: `iret` transition to ring 3 with TSS-managed kernel stack.
- Syscalls: `int 0x80` first, `sysenter` later for fast paths.
- QEMU: `qemu-system-i386` boots `kernel.bin` and validates the debug kernel
  through serial output and the debug-exit device.

## Native execution

The native execution backend targets a 32-bit PAE/SSE2/NX-capable CPU. This
retains the `i386` architecture profile and its ELF32 ABI; it does not claim
that an original 80386 can enforce NX. QEMU's default `qemu32` has no NX,
so native application execution explicitly uses `-cpu max`.

- PAE page tables provide supervisor-only kernel identity mappings and separate
  4 KiB user mappings in `[0x40000000, 0x80000000)`, including hardware NX.
- TSS/IDT entry uses ring 3, `int $0x80`, `iret`, and the actual PIT IRQ0.
- Each frame preserves general registers, x87/SSE state, segment selectors and
  FS/GS TLS bases. The backend restores kernel FP/TLS before invoking C++.
- The syscall ABI uses EAX for the number and EBX/ECX/EDX/ESI/EDI/EBP for arguments.
  The result is a signed 32-bit EAX value. This is the project's native ABI.
- Kernel C++ uses `-mno-sse -mno-sse2` until an earlier bootstrap establishes SSE;
  the native backend enables FXSR/SSE2 before restoring user state.

Run the isolated hardware probe without changing xmake configuration:

```sh
python3 scripts/test_native_i386.py --toolchain toolchains/i386-elf
```

It checks actual ring-3 entry, syscall continuation, distinct address spaces,
SSE preservation, PIT preemption, supervisor isolation, read-only pages, a
branch into an NX page, unmapped addresses, invalid instructions and safe copies.

The probe also checks x87 state, actual FS/GS addressing, changed user segment
selectors/DF, kernel SSE/TLS restoration, and a user SS descriptor with a
nonzero base. For i386, `UserFrame.sp` is architectural ESP; the saved SS
selector determines the linear stack address used by permission validation.

A separate supervisor exception probe checks that CPL0 faults stay kernel
faults instead of dereferencing the active user frame:

```sh
python3 scripts/test_native_i386.py --toolchain toolchains/i386-elf --kernel-fault
```
