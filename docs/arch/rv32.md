# rv32

The profile boots the standalone kernel on QEMU `virt` with
`qemu-system-riscv32 -M virt -bios none`. The kernel starts at `0x80000000`
in machine mode. The current cross compiler targets RV32IMAFDC with the ILP32D
ABI; native execution requires the F/D extensions and Sv32.

## Native execution

`src/arch/rv32/execution.cpp` and `execution.S` implement the shared native
execution contract. `mret` enters U-mode with Sv32 active, and a machine trap
vector captures system calls, CLINT timer interrupts and user faults. The
kernel remains in M-mode and does not appear in the user page tables. This
path is distinct from the supervisor-mode transition metadata in `ops.cpp`.

Each address space has a 4 KiB root with 1024 entries and up to 16 leaf tables.
Up to 128 supplied 4 KiB backing pages are mapped in
`0x40000000 <= address < 0x80000000`; there are 16 address-space slots. User PTEs
enforce read/write/execute permissions, and mapping validation rejects writable
executable pages, duplicate virtual pages, bad alignment and out-of-range pages.
Copies validate the complete user range before accessing the kernel-owned
physical backing. Generations reject stale address-space handles.

The bridge preserves all user integer registers, including `gp` and `tp`, all
32 double-width floating-point registers and FCSR. It restores kernel
callee-saved registers, FP state when enabled, trap CSRs and the previous timer
compare. User `ecall` uses `a7` for the syscall number, `a0` through `a5` for
arguments and `a0` for the result. CLINT delivers a roughly 10 ms quantum;
64-bit counter reads and compare writes use RV32-safe sequences.

## Hardware validation

From the kernel repository:

```sh
python3 scripts/test_native_rv32.py
```

The isolated freestanding probe builds into `build/native-tests/rv32` without
changing the xmake configuration. `--toolchain`, `--qemu` and `--output` override
tool paths and output location. It writes `probe.elf` and `serial.log`, requires
QEMU to exit successfully and checks `RV32_NATIVE_PASS scope=hardware`.

The user probe executes real ecalls and returns, checks timer preemption and
continued register state, provokes read-only, NX and kernel-address page faults,
checks full-width FP values, and switches A-to-B-to-A between address spaces
with different physical backing at the same virtual address. It also checks
safe-copy boundaries, W^X policy, bad stack rejection and stale handles.
Unexpected timer delivery before an expected syscall or fault is resumed with
a bounded retry count.

The regular xmake QEMU kernel suite remains separate from this hardware probe.
Distribution ELF32 loading and application integration are separate OS tests;
this probe does not claim POSIX completeness, device IRQ delivery or application
compatibility.

## Current limits

- Only boot hart 0 executes native user code; no hardware SMP dispatch or nested
  native entry is supported.
- The kernel requires QEMU's machine-mode boot and platform CLINT/PMP layout;
  this is not an SBI/supervisor-mode backend.
- Physical backing and page-table capacities are fixed; there is no demand
  paging, copy-on-write or dynamic address-space growth here.
- Native traps currently own the machine timer during a quantum. PLIC device
  interrupts and RISC-V vector state are outside this backend.

The boot platform also supplies NS16550 UART, ramfb output and virtio-mmio
keyboard/mouse support independently of native execution.
