# Legacy journal recovery with startup storage

The optional permanent startup workspace preserves the mounted dirty-root
recovery profiles for structural inode metadata, first/next block allocation,
create and rename. The checksummed active descriptor selects the corresponding
strict legacy proof while the original Owner, cache, registered Session and
unpublished mount remain retained. A private selection retains the exact initial
journal head and descriptor; diagnostic reports cannot select a writer.

The selected completion proves commit, payload, all admitted home mixtures and
the final filesystem view, then physically rereads the original head and
descriptor before any WRITE/FLUSH. A changed locator refuses. The original
completion ordering is shared through a private prepared execution method;
public completion still prepares and executes exactly once. Large readback
images reuse the completion's member storage.

Namespace/reclaim recognizers keep priority. Their recognized malformed inputs
never enter legacy recovery. New typed zero-truncate/allocated-empty recognizers
must have the same priority and refusal rule during subsequent composition.
The fixed 32 MiB bootstrap locator and serialized caller exclusion remain
requirements. Failed transport quarantines the same original Session; terminal
startup observations reflect all six actual counters, while the inherited local
success-only shadow is not claimed complete after failure.

`ext4_mounted_legacy_startup_tests.cpp` executes hosted mounted recovery, compares
complete final images with the original Owner checkpoint, tests all first/next/
create/rename home mixtures, public callback exclusion, invalid descriptor/
commit/payload controls and failed WRITE/FLUSH before and after completion. This
is source/model evidence. Whole-route reservations, SDK export/consumption,
target stack chains, native guest restart, SMP and physical durability remain
separate integration gates.

Call-only dispatch guards check the retained original Session, private selected
family and workspace authority after runtime geometry callbacks and before
physical READ/WRITE/FLUSH. READ dispatch forwards the direct scope and an optional
external in-flight Hook, then rechecks the scope after the Hook. A refused
pretransport dispatch retains its attempted counter without completion credit.
Geometry drift controls verify that legacy READ6 is refused with five physical
READs and no WRITE/FLUSH; WRITE and FLUSH controls likewise stop before transport.

Post-recovery canonical misses retain a separate call-only guard for the original
Session, Owner, workspace, selected family, loading slot and Pin. Deferred begin
runs outside the cache lock so the outer domain can be checked without recursive
locking. The guard rechecks these identities at every in-flight boundary and
adopts only exact successful READ progress. Canonical-miss geometry controls
verify refusal before the first physical miss and after a successful physical
READ or post-READ geometry callback, preserving completed legacy recovery media
and all six actual counters. Post-transport drift receives no completion credit.
